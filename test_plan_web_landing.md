# Тест-план проекта: Лендинг корпоративного обучения (веб-лендинг)

**Сайт:** Демо-стенд (публичный лендинг)

---

## 1. Вступление

Настоящий документ является тест-планом для веб-страницы «Корпоративное обучение».

В нём определены цели и объём тестирования (что входит и что исключено), критерии приёмки/приостановки, применяемые подходы и техники (функциональное, UI, кросс-браузерное, адаптивность), необходимые ресурсы и окружение, график работ, роли/ответственности и риски.

Документ служит основой для согласования ожиданий между заказчиком (корпоративный отдел), разработкой и QA и используется для планирования, контроля и отчётности по тестированию лендинга.

---

## 2. Функциональности, которые будут протестированы

| Категория | Что проверяется |
|-----------|----------------|
| **Основной контент** | Заголовки H1/H2, подзаголовки, тексты блоков, списки («Технические навыки», «Мягкие навыки»), иконки/изображения |
| **Программы обучения** | Отображение 4 программ (ИИ-трансформация, Управление проектами, Анализ данных, Лидерство); текст описания каждой |
| **Форма заявки** | Поля ввода (имя, контактные данные, возможно, выбор программы), валидация, отправка, сообщения об успехе/ошибке |
| **Часто задаваемые вопросы (FAQ)** | Раскрывающиеся блоки с ответами на вопросы (возраст, поступление, гражданство и т.д.) |
| **Навигация и ссылки** | Меню сайта, якорные ссылки (если есть), внешние ссылки, кнопка отправки формы |
| **Блок «Обратная связь»** | Форма для вопроса (если отделена от основной заявки), ссылка/кнопка для связи |

---

## 3. НЕ будут протестированы

| Область | Причина исключения |
|---------|--------------------|
| Личный кабинет пользователя/корпоративный портал | Требует авторизации и отдельных учётных записей; выходит за рамки публичного лендинга |
| Платежи и бронирование обучения | Отсутствуют на данной странице (нет интеграции с платёжными шлюзами) |
| Нативные мобильные приложения | План охватывает только веб-клиент (десктоп/мобильные браузеры) |
| Бэкенд-логика отправки форм (API, база данных) | Требует доступа к серверной части и отдельного тестового стенда |
| Нагрузочное и стресс-тестирование | Отсутствуют целевые SLA и выделенный стенд в рамках данного плана |
| SEO/индексация, аналитические теги (метрики) | Относятся к маркетинговой/аналитической инфраструктуре; тестируются другими командами |
| Доступность (a11y) для людей с ограничениями | Не приоритезировано в текущем релизе лендинга |

## 4. Тестовые единицы

| Модуль | Что проверяется |
|--------|----------------|
| **Шапка и заголовки** | Отображение H1 «Корпоративное обучение руководителей цифровым технологиям», подзаголовков, соответствие макету |
| **Блоки навыков** | Перечни «Технические навыки» (5 пунктов) и «Мягкие навыки» (5 пунктов) — каждый пункт отображается, иконка + текст |
| **Программы обучения** | 4 карточки программ: название, описание, возможная кнопка «Подробнее» или ссылка. Клик ведёт на правильную страницу/открывает модальное окно |
| **Форма заявки** | Поля: «Имя», «Телефон/E-mail», возможно, «Выберите программу» (дропдаун). Валидация: пустые поля, неверный формат. Отправка: появление сообщения об успехе |
| **FAQ (аккордеон)** | При клике на вопрос открывается соответствующий ответ; повторный клик закрывает. Текст ответов соответствует вопросу |
| **Блок обратной связи** | Поле для ввода текста вопроса/комментария, кнопка отправки. Валидация: пустое поле, слишком длинный текст, отправка |
| **Футер** | Ссылки на соцсети (если есть), контактная информация, юридический текст (если применимо) |

## 8. Задачи тестировщиков

| Задача | Описание |
|--------|----------|
| Подготовка тестовой документации | Составление чек-листов и тест-кейсов для формы заявки, FAQ, кросс-браузерной проверки |
| Подготовка тестовых данных | E-mail тестовый (test@example.com), телефон (+ 7 999 123-45-67), варианты выбора программ |
| Прогоны по матрице окружений | Выполнение тестов на Desktop (Win/Mac) и Mobile (iOS/Android), фиксация артефактов (скриншоты, видео) |
| Заведение дефектов | Создание баг-репортов с шагами, скринами, приоритетами; ретест фиксов |
| Отчётность | Ежедневный статус (после каждого прогона), итоговый отчёт с метриками (Пройдено/Не пройдено, критичные баги) |

## 9. Потребности в окружении

| Категория | Требования |
|-----------|------------|
| **ОС** | Windows 10/11, macOS 14 (Sonoma или новее), iOS 16+, Android 13+ |
| **Браузеры** | Chrome (стабильная версия), Edge, Firefox, Safari (macOS/iOS), Samsung Internet (Android, опционально) |
| **Разрешения** | Desktop: 1920×1080, 1366×768; Tablet: 768×1024 (iPad), 800×1280 (Android); Mobile: 375×667 (iPhone SE/8), 390×844 (iPhone 12/13/14), 360×800 (Android) |
| **Инструменты** | DevTools (Network/Console/Responsive), средство скриншотов, трекер дефектов (YouTrack/Jira/Google Sheets), инструменты аннотаций |
| **Сеть** | Стабильное подключение (провод/стабильный Wi-Fi); без VPN или с VPN, если сайт блокируется в регионе |
| **Аккаунты** | Не требуются (публичный лендинг) |

## 10. Персонал и обучение

| Роль | Ответственность | Резерв |
|------|----------------|--------|
| **Test Lead** | Составление плана, матрицы окружений, приёмка тестов, коммуникация с заказчиком, итоговый отчёт | Manual QA (старший) |
| **Manual QA (1–2 чел.)** | Дизайн и прогоны кейсов, артефакты, заведение/ретест дефектов | Manual QA (другой) |
| **Контент-менеджер (внешний)** | Проверка орфографии/смысла текстов (привлекается на этапе контент-тестирования) | — |

**Обучение/бриф:**
- Краткий обзор целевой аудитории (корпоративные клиенты) и бизнес-целей (лидогенерация через форму заявки).
- Правила фиксации артефактов (скриншоты всей страницы/блока, видео работы аккордеона для мобильных).
